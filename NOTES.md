# Робочі нотатки

# Лабораторна робота 2

У NOTES.md потрібно обґрунтувати вибір типів для двох-трьох властивостей.

Для властивості CookingTime використано тип int, оскільки час приготування зручно зберігати як ціле число хвилин.

Для властивостей CreatedOn та LastCookedOn використано DateOnly, оскільки для них важлива саме календарна дата, а інформація про час доби не потрібна.

Властивість Description має тип string?, оскільки опис рецепта може бути відсутнім.

Тип-перелік у базовій моделі не використовується, оскільки категорії страв будуть реалізовані окремим довідником.

# Лабораторна робота 3

Для контексту даних створено клас `RecipesContext`, який успадковується від `DbContext`. Властивість `Recipes` типу `DbSet<Recipe>` представляє набір рецептів і відповідає таблиці в базі даних.

Для реєстрації контексту використано `AddDbContextFactory<RecipesContext>`, оскільки фабрика дає змогу створювати окремі екземпляри контексту для роботи з базою даних.

Для зберігання даних використовується SQLite, яка не потребує окремого сервера та зберігає базу в одному файлі `recipes.db`.

Для керування структурою бази даних використовуються міграції Entity Framework Core. Перша міграція `Init` визначає початкову структуру бази даних відповідно до моделей застосунку.

Перетворення властивостей типу `decimal` на `double` не використовується, оскільки в поточній моделі немає властивостей типу `decimal`.
